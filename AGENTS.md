# AGENTS.md

Instructions for agents working in this repository.

## Project

Standalone Postman-style environment manager for `.env` files.

- Real `.env` files are the source of truth.
- Metadata lives in `.envh.json` and never contains values.
- Core Node library + CLI (`envh`) in `packages/core`.
- Thin VS Code extension in `packages/vscode`.
- Authoritative design: `env-manager-plan.md`.

At the time of writing, the repository is at the planning stage; Phase 0 scaffolding has not been created yet.

## Hard rules

1. **No dotenvx.** No dependency, import, CLI call, or decryption through dotenvx.
2. **Do not patch or fork `dotenv-vscode`.** This is a standalone project.
3. **No values in metadata or logs.** `.envh.json` stores names, paths, colors, order, active state, and swap state only.
4. **Encrypted values are read-only.** Detect `encrypted:`, show a lock, preserve the line, never rewrite or decrypt.
5. **No network calls or telemetry.**
6. **Core must not import `vscode`.** Extension code must stay thin and delegate to core.
7. **Do not add a `.env` parser dependency** (`dotenv` included). The offset-preserving parser is local.
8. Keep the project runnable with plain JavaScript (CommonJS), Node 18+ for consumers, Node 22 for development.

## Layout

```text
packages/core/
  bin/envh.js
  lib/            # pure logic + Node fs adapters
  test/           # node:test suites
packages/vscode/
  extension.js
  lib/            # store, tree, status bar, commands, debug, tasks
  media/icon.svg
  dist/           # generated by esbuild, not committed
scripts/
  build.js
  package.js
  install.js
  check-no-dotenvx.js
```

Expected core modules: `env-vars`, `metadata`, `sidecar`, `discovery`, `layers`, `runner`, `swap`, `postman`, `gitignore`, `shell`, `fsx`, `paths`, `errors`. Keep pure logic separate from filesystem and VS Code code.

```sh

```

Then run **Developer: Reload Window**.

## Architecture

- `packages/core` owns discovery, parsing/editing, metadata, layering, running, swapping, Postman import, and gitignore checks.
- `packages/vscode` owns VS Code UI/adapters only.
- `esbuild` bundles `packages/vscode/extension.js` to `dist/extension.js` and the CLI entry to `dist/envh.js`. `vscode` is external.
- Extension packaging uses `vsce package --no-dependencies` because dependencies are bundled.

## Data and layering

- Sidecar path: `<project-root>/.envh.json`.
- Discovery: `**/.env`, `**/.env.*`; exclude examples, templates, `.env.keys*`, `.env.vault`, `.envh.json`, `node_modules`, and `.git`.
- Base layer: `.env` in the same directory as the active file.
- Active layer loads after the base; later values win.
- Swap loads only the swap target and bypasses base layering.
- Runner: file values override the parent environment by default; `--no-override` reverses that.
- Debug: merged file values are applied, then `config.env` wins.
- Encrypted values are passed through by the runner with a warning; debug skips them and warns.

## Code style

- `standard` style: two spaces, single quotes, no semicolons.
- CommonJS (`require`/`module.exports`).
- Prefer small pure functions and dependency injection over global state.
- Typed error codes live in `lib/errors.js`; messages must not contain values.
- Atomic writes via a temp file + rename.
- Preserve file formatting: comments, blank lines, quoting, `export` prefixes, CRLF, BOM, trailing newline.
- Avoid broad rewrites; make targeted edits.

## Testing

- Use `node:test` and `node:assert/strict`.
- Use temporary directories (`fs.mkdtemp`), never the real workspace.
- Tests must be offline and must not download VS Code.
- Cover pure modules first; add CLI integration tests by spawning `node packages/core/bin/envh.js`.
- Extension pure helpers may be tested under `packages/vscode/test/unit` without importing `vscode`.
- Before finishing a change, run at minimum: `npx standard`, `npm test`, `npm run check:no-dotenvx`, and `npm run build` when extension code changed.

## Extension conventions

- Settings prefix: `envHandler.*`.
- Debug integration defaults to off.
- `terminalMode`: `none` | `task` | `swap`.
- `extensionKind`: workspace; virtual workspaces are unsupported.
- Untrusted workspaces are read-only: no edits, runner, swap, git, or import.
- Multi-root: one independent active environment per workspace folder.
- Single-root: flat environment list.
- Do not add a custom editor, language contribution, cloaking, or autocomplete; the official Dotenv extension may coexist.
- Values are masked by default; revealing is transient.

## Safety checklist

- No secrets in metadata, tree tooltips, errors, or logs by default.
- Warn when a plaintext layer is not gitignored; never edit `.gitignore` without explicit user action.
- Swap must confirm, back up, store state, and support restore.
- Do not auto-restore swap on deactivate.
- Do not overwrite a corrupt `.envh.json`; report it.

## Workflow

- Work in small phases (see `env-manager-plan.md`).
- Update `README.md`, `CHANGELOG.md`, and `env-manager-plan.md` when behavior or commands change.
- If a requirement is ambiguous or conflicts with these rules, ask before implementing.
